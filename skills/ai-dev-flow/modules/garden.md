# 复盘

每周一次，看这一周**合进去的东西**，让下一周更容易。`/next` 开场发现 `LESSONS.md` 的 `reviewed-on` 已在 7 天前就先做（`skills/next/SKILL.md` 第 1 节）；用户说"复盘"时当场做。

## 1. 步骤

1. 列出 `LESSONS.md` 的 `reviewed-through` 之后合进主干的提交（没有 `LESSONS.md` 的先建一个，看最近 7 天）。
2. 找三类问题：**返工的**（后面有提交"修复"指向它，或被 revert）；**不该合的**（超出目标、违反已有标准、本该单向门却自走）；**验证太薄的**（正文没有"跑了""改坏"，改了功能却没有真实数据一行）。
3. 每个问题写成一条教训：
   ```
   ## <规则，一句话>
   原因：<为什么>
   证据：<提交 sha>
   Seen：<不同日期的数量>（<日期>）
   ```
   已有的更新证据和 Seen。
4. **升级**：Seen 达到 2 的，改成更硬的形态，选第一个做得到的：架构或类型让错误写不出来；lint、测试、hook 让它自动报错；最后才是一条写进文档的规则。升级是一项改动，照常证明、审查；没挡住当前项的先写"待放行"。该改的是 skill 的（换项目也会犯），写进 ai-dev-flow 仓库的 `docs/requests.md`（`portfolio.md` 第 3 节）。只出现过一次、两周没再犯的教训删掉。
5. 把 `reviewed-through` 改成这次看到的最新提交，`reviewed-on` 改成今天。

## 2. 复盘摘要

白话，一屏以内，同时写进 `.agents/digest/<日期>.md`（不入库）：

```
这一周：合了 N 项（每项一句）
北极星：<最近一次>（上次 <数字>）
返工：<返工项数> / <合并项数>
新教训：<一句一条>；升级了：<哪条变成了什么>
待清理：<已合并没删的分支和 worktree；没有写"无">
要你做：<无 / 队列里待用户、待放行的逐条，附推荐>
建议：<无 / 信任等级升降、某条规则拖慢了工作却没防住过问题、两条规则矛盾>
```

结束时照 `/next` 第 6 节发通知。

## 3. 清理

已合并的分支和 worktree 跑 `cleanup.ps1` 直接删；队列关掉过时的、合并重复的；`AGENTS.md` 压回 100 行以内的目录；状态类文档压到一页白话。删死代码和不再用的脚本是一项改动，照常走。
